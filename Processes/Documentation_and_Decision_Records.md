# Research Lab — навигация и журналы решений

**Статус:** действующее правило по решению Owner от 09.10.2026  
**Смысловой язык:** русский; применима [Методология v0.4](../Methodology/methodology_v0.4.md) §1.1.

## 1. Три уровня и точка входа

| Уровень | Точка входа | Что показывает |
|---|---|---|
| Вся лаборатория | [корневой README](../README.md) и [журнал лаборатории](../DECISIONS.md) | действующие проекты, запросы в Formation, общие правила и решения Owner |
| Конкретное исследование | `Research/<ID>/README.md` и `Research/<ID>/DECISIONS.md` | вопрос, протокол, книги/корпуса, текущий gate, проектные решения |
| Этап/книжный цикл | `Research/<ID>/Research/<CORPUS>/README.md` и `DECISIONS.md` рядом с ним | поэтапная карта, точный принятый artifact, открытые вопросы, решения и следующий шаг |

В проекте без книжного корпуса третий уровень размещается рядом с его stage outputs по принятому Protocol. Stage sections в одном журнале допустимы; отдельный файл каждого этапа нужен только при реальном объёме, а не автоматически.

Запрос в Formation остаётся `RQ-*` в [карте запросов](./Research_Request_Map.md) и `Development/Formations/`. Номер нового `IP-*` и проектный каталог не появляются автоматически от факта Formation или Installation.

## 2. Разделение навигации и решений

README — короткая обновляемая точка входа. Он содержит дату сверки, состояние, ответственного, действующие ссылки, открытые зависимости, следующий gate и ссылку на решение. README не принимает этап и не заменяет журнал.

DECISIONS.md — журнал решений своего уровня. Новые решения добавляются append-only с уникальным локальным ID, датой, владельцем решения, точным target (ссылка на файл и при необходимости неизменяемый commit), статусом, основанием, границей полномочий и следующим owner/gate. Не копировать целые результаты из исследовательских файлов. Если решение принято в другом историческом журнале, новый журнал даёт ссылку и короткое состояние, не объявляя это новым решением.

В споре между навигацией и действительным решением действует последнее полномочное решение по данному объекту. При этом устаревший README исправляется в том же handoff; правило приоритета не является разрешением оставлять навигацию устаревшей.

## 3. Ответственность и момент обновления

- **Researcher** сдаёт artifact и точный handoff; не помечает собственный результат принятым.
- **Project Lead** при принятии/возврате stage handoff обновляет журнал и README уровня этапа, а также проектный README/журнал, если изменился gate проекта. Это часть закрытия его назначения.
- **Research Lab Director** ведёт карту запросов и лабораторную навигацию при Formation, учреждении/закрытии проекта и общих изменениях; сверяет межпроектные ссылки. Owner принимает решения за пределами делегированных полномочий.
- **Owner** задаёт новый gate или утверждает изменение Methodology. Ветка, оформляющая его решение, синхронизирует затронутые точки входа и указывает источник полномочий.

При append-only handoff исполнитель проверяет не только собственную строку, но и ближайший родительский README. Если обновление не выполнено, handoff прямо отмечает навигационный долг и не выдаёт README за актуальный источник состояния. Техническое обновление навигации не активирует новую роль или стадию.

## 4. Редакции и происхождение

`rr-002` у IP-001 означает поколение/этап результата, а `-R1`, `-R2` — последовательные цельные редакции одного target. Большее число не означает acceptance. Действующая редакция названа в статусной строке и привязана к решению; исходные редакции сохраняются по ссылке или неизменяемому commit. `v0.4` Методологии — версия нормативного документа, отдельная шкала.

Для нового проекта названия журналов могут быть одинаковыми (`DECISIONS.md`), потому что их отличает каталог `Research/<ID>/`. Корневой журнал не смешивает все stage events в один бесконечный файл.

## 5. Переход с RL-WAVE-2

[RL-WAVE-2/RUN.md](../Development/Validation-Runs/RL-WAVE-2/RUN.md) сохраняется как исторический append-only record Events 001–072. Его ранние Current State/Process Map устарели; после Event 072 он не служит главным навигационным экраном. Файл не переименовывается и не переписывается. Новые журналы ссылаются на точные Events/commits, не присваивают прежним решениям новых дат и не заменяют их.

Новые решения после перехода записываются на соответствующем уровне. Если одно решение затрагивает несколько уровней, полный текст живёт в журнале компетентного уровня; остальные содержат ссылку и короткое следствие.

## 6. Язык

Вопросы, статусы в человеческом объяснении, решения, причины, ограничения и следующий шаг пишутся по-русски. Коды, имена файлов, установленные controlled statuses и цитаты источников могут оставаться на языке оригинала с русским объяснением. Не проводить массовый перевод исторических записей без отдельного назначения.
