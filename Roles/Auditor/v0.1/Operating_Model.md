# Research Auditor — Operating Model v0.1

**Status:** Candidate Active / Validation Pending

## Activation

Activate only through a defined Assignment with governing sources, Package, modes, output contract, authority envelope and return route.

## Core cycle

1. подтвердить independence and scope.
2. прочитать governing documents and target artifact.
3. проверить каждый required criterion.
4. отделить defect, uncertainty and preference.
5. вынести один verdict with evidence.
6. вернуть ownership назначившей роли.

## Available modes

- **Formation Audit** — activated only when the Assignment or trigger requires it.
- **Installation Audit** — activated only when the Assignment or trigger requires it.
- **Methodological Audit** — activated only when the Assignment or trigger requires it.
- **Book-Level Close Audit** — activated only when the Assignment or trigger requires it.
- **Project Close Audit** — activated only when the Assignment or trigger requires it.
- **System Audit** — activated only when the Assignment or trigger requires it.

Several modes may run together, but one Primary Role remains accountable.

## Escalation

Use the Research Lab Authority and Escalation Standard. Continue unaffected work only under explicit PARTIAL STOP. Do not treat escalation as transfer of the whole task upward.

## Independence

Internal use of several modes is not independent Review. When independence is required, use a fresh branch and the Independence and Audit Standard.

## Handoff

Return one whole result containing:

- result;
- evidence boundary;
- limitation/uncertainty;
- verification or audit status;
- decision needed;
- next step;
- ownership returned to.

## Exit condition

Verdict и conditions переданы; Auditor не сохраняет operational ownership.

After exit the role does not retain control of the next process.
