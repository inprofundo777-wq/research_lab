### Что может стать достаточным основанием Assessor

Предлагаемый профиль:
- **CTX:** восстановление локального контекста/субъекта/формы свидетельства, сопоставление конкурирующих интерпретаций и ограничений.
- **LANG:** работа с идентифицируемым Greek text, синтаксисом/семантикой и переводческой зависимостью; воспроизводимое различение текстового основания и собственного толкования.
- **TEXT:** работа с проверяемыми данными вариантов/аппарата, различение вариантов, синтаксиса и референта; отсутствие вывода «аппарат подтвердил» без доступа.

Пригодные evidence: ранее самостоятельно выполненные **и отдельно предметно оценённые** работы/образцы с точным source path, авторством, решением проверявшего, допущенным доменом и ограничениями; для реального специалиста — проверяемая релевантная квалификация/опыт в дополнение к предметному scope. Допустима квалификация в одном/двух доменах с честным разделением функций.

Для AI-ветки не указывать диплом/опыт человека; модельное имя, уверенный тон и самодекларация не competence evidence. Одинаковая модель в разных чатах не считается разнообразием моделей; fresh branch помогает отделить производство, но не устраняет общие ошибки модели. Если есть отдельное проверяемое основание назначения AI-предметного оценщика, оно фиксируется Owner, а не присваивается этой веткой Lead.

В repository record для **конкретного нового оценщика** такого evidence сейчас не установлено. Это открытая зависимость, а не отрицательное решение об интеллекте модели. Если evidence отсутствует:
1. новая Assessor-ветка может после разрешения восстановить роль/независимость и собрать **уже существующий** eligibility evidence; не оценивает C01–C03 и не создаёт новую предметную пробу на них;
2. Owner может закрепить допуск по реальным представленным основаниям, выбрать компетентного человека/иного проверяющего или разделить домены;
3. если достаточного основания нет — **ASSESSOR NOT ESTABLISHED / CAPABILITY VERDICT BLOCKED**, не экспертный PASS по взаимному согласию двух чатов.

Новую проверку компетенции самого оценщика можно предложить как отдельный bounded route, но **она не добавлена автоматически** к трёхслучайной CV и не запускается этим документом. Это не бесконечная цепочка оценщиков.

## 4. Источниковая готовность — после разрешения P0, до C0

Нужен единый регистр **CV-ACTS-IV-SOURCES-v0.1**, подготовленный в разрешённой recovery/readiness операции, без ответов на C01–C03:
- RST: approved carrier принятого Stage 1, преимущественно bible.by; резерв — только ранее разрешённые носители и условия;
- Greek: конкретное доступное идентифицируемое первичное издание, версия/редакция, устойчивый путь к нужным verses;
- переводы: идентифицируемые версии с проверяемой цитатой нужного места; не анонимные пересказы;
- для C03: отдельно критический аппарат/документированные данные вариантов с точным изданием и адресом; текст издания сам по себе не доказывает apparatus;
- достаточность для оценки: Assessor должен иметь возможность проверить конкретное cited evidence, а не только прочитать пересказ кандидата.

Никакие источники/базы в этой подготовке не открывались и не заявлены доступными по факту. Выбор конкретных доступных изданий в утверждённых категориях можно делегировать P0; изменение категории/допуска требует явной фиксации. Недоступность обозначается до анализа.

Readiness по **CTX/LANG/TEXT отдельно**:
- READY — есть explicit scope и проверяемые источники;
- LIMITED — указано, какая часть пробы может быть выполнена и какая останется неоценённой;
- BLOCKED — нет необходимого source/assessor/authority.

Отсутствие TEXT не отменяет доступный CTX/LANG по отдельно разрешённому scope, но C03 нельзя получить ложный полный PASS. Если Owner разрешит только сбор eligibility/readiness, наличие READY не запускает C0 автоматически.

**Primary Role:** Researcher v0.1. **Package:** C. **Function:** временная предметная оценка способности; **Mode:** controlled Independent Review кандидатного output, только explicit Owner-assigned scope.  
**Output Contract:** ACTS-IV-CV-EVAL-OC-v0.1, §5.4 MV-пакета.

1. Owner принимает/возвращает эту конкретизацию; утверждает **только требуемый объём** следующего шага.
2. Если разрешено только P0: новая ветка Assessor и Candidate возвращают eligibility/readiness без sample reasoning. Lead представляет полноту/конфликты; Owner закрепляет предметное основание допуска Assessor.

4. Candidate выполняет C01–C03 → Lead проверяет договор → допущенный Assessor оценивает immutable output → Lead возвращает матрицу/ограничения Owner.
5. Owner отдельно решает **Gate B производственной MV** по фактическому результату. Ни PASS Candidate, ни approval дизайна не активируют её. Исторический слой/Stage 4/book close закрыты.

Это подготовительный маршрут внутри Gate A, уже предусмотренный утверждённым пакетом; не новое обязательное правило лаборатории.
