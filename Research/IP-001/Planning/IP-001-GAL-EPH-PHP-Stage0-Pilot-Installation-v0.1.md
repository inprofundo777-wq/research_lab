## 4. PILOT-S0-OC-v0.1 — предлагаемый местный договор Stage 0

Договор применяется к каждой карточке отдельно **только после** независимого местного verdict, Owner-разрешения и адресного назначения Lead. Пилот не активирует его исполнение самим наличием текста.

Каждый отдельный rr-000 содержит:
1. Один местный Lock с указанием общего листа/карточки, действительного Owner-разрешения, источника, редакции или её неизвестности, времени доступа и явной допусковой записи Lead по SRC/EXP до отбора.
2. Ledger всех глав: GAL 6/6, EPH 6/6, PHP 4/4 — глава/адрес/словесные границы/охват, кандидаты или русское объяснение существенного неотбора; нет усечённого остатка вместо всей книги.
3. Собственные C001…: точный locus и достаточный контекст, применимый критерий 1–5, причина дальнейшего изучения, значимая неопределённость субъекта/времени/речевого уровня. Критерий 1 — прямое приписывание Христу; неустановленный титул не размечать как уже прямое приписывание. Не присваивать окончательные INCLUDE/BORDERLINE/CONTEXTUAL/EXCLUDE Stage 1.
4. Собственные Q001… только при существенной зависимости: кто/когда/этап/источник, locus/C, альтернативы, влияние на будущий вывод, нужная проверка/источник, статус OPEN / NOT VERIFIED и ответственный. Отсутствие новых Q возможно, если фактически обосновано; квот нет.
5. Self-check полноты главы за главой, ID/языка/ссылок/критериев/изолированности и сохранения единичного/отрицательного/пограничного; существенные source/disclosure ограничения.
6. После сохранения и чтения обратно по immutable commit — отдельный книжный handoff с точными commit/blob, фактическим охватом/C/Q, поздними находками, ограничениями и статусом **STAGE 0 SUBMITTED / NOT ACCEPTED → Lead**. Три книги — три rr-000 и три handoff; один не заменяет остальные.

**Lead ACCEPT/RETURN отдельно:** source/disclosure и допуск до отбора; полный последовательный охват; точность/восстановимость C/Criteria; Q/происхождение; язык/субъекты/время/изоляция; отсутствие Stage 1–4. RETURN содержит точные книгу/C/Q/locus и нужный цельный результат. Это внутренняя договорная приёмка, не независимый предметный PASS.

Можно исполнять в одном рабочем цикле, но целесообразно последовательно GAL → EPH → PHP, без смешивания записей. Точное разрешение может охватывать любое подмножество книг; неразрешённая/блокированная книга пропускается только при явном разделении полномочий. Не начинать Stage 1 по GAL, пока Owner отдельно его не разрешит после принятого Stage 0.

## 5. Source / disclosure / ресурс и STOP

**До первого отбора каждой книги** нужны её SRC-GAL/EPH/PHP и EXP-GAL/EPH/PHP: фактический полный непрерывный RST с экспортом/каждоглавными границами и раскрытие собственных прежних чатов/памяти/участия/решений/старого ключа. Две источниковые страницы, отсутствие папки и новый чат не доказывают готовности. Карточки фиксируют реальный проверенный объём и неизвестное. Lead явно принимает местные evidence и закрывает применимые условия до отбора; readiness не наследуется.

Иной носитель того же RST требует раскрытия/проверки тождества Lead до применения. Существенная смена текста/корпуса/критериев, старый ключ или неразрешённая экспозиция → STOP затронутого объёма → Lead → Director/Owner; созданное сохраняется.

При блоке одной книги **Lead фиксирует явный PARTIAL STOP**: что остановлено, почему входы/разрешения других книг остаются действительны и какую работу можно продолжать. До такой диспозиции не продолжать по аналогии. Общий дефект нормы/носителя или межкнижная утечка останавливает весь затронутый объём.

Конкретные CTX/LANG/TEXT оценщик/доказанный допуск/независимость, дополнительные издания/аппарат и доступность не установлены. После появления местных Q ресурсная карта уточняется по реальным зависимостям; новая полная P0/capability автоматически не запускается. Нехватка позднего reviewer не отменяет отдельно разрешённый ранний этап, но не позволяет закрыть спорный вывод. Verification/MV, Stage 4/книжный итог и NT-T здесь не разрешены.

## 6. Границы совместного независимого Audit

Installation Audit входит в Scoped Active Auditor v0.1; аудит установки Lead назначает Director по Independence Standard. Автор пакета не может быть его независимым Auditor. Решение о допустимости **конкретного совместного назначения** принимает Director по D072, а не Lead.

**Объект:** точные общий лист + три карточки и принятый R1/A/PASS/D029. Проверяются применение норм, корпус/ID/targets/история, частичная source readiness и достаточность полного source gate, местное disclosure/disposition, жанровая настройка/договор, полномочия/раздельные Owner gates/PARTIAL STOP и будущий ресурс. Отдельно проверить, допустима ли раскрытая осведомлённость одного чата, либо одной книге нужна другая ветка. Библейские ответы не исследуются.

**Предлагаемый output:** `Research/IP-001/Review/IP-001-GAL-EPH-PHP-Pilot-Installation-Audit-v0.1.md`, разделы GAL / EPH / PHP. В каждом — точные shared/card commit/blob, evidence/findings/независимость, собственный verdict **PASS / PASS WITH CONDITIONS / RETURN / BLOCK / ESCALATE**, условия до запуска/поздние условия, return и состояние соседних объектов. Общий finding явно перечисляет затронутые книги. Общий PASS без трёх книжных verdict недостаточен.

Если Director видит пробел мандата для единого отчёта — три местных отчёта в одном установочном заходе с тем же shared target и отдельными verdict. Меняется упаковка, не требования/роль; действительное назначение и формат фиксирует Director. **Сейчас Auditor не назначен, Audit не активирован.**
