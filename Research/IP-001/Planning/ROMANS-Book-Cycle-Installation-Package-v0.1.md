## 3. Изоляция исторического поколения

До самостоятельной фиксации и принятия нового Stage 0–3 запрещены как исследовательские inputs: все прежние Romans doc-*, пилотные rr-*, Summary.md, Book.md, старые карты, списки мест и их содержательные обзоры/чужие объяснения. Отчёт Pilot Review не передаётся Researcher как источник локальных ответов; достаточные методологические находки уже включены в действующие нормы.

Разрешены governance, настоящий пакет, тексты источников и результаты только текущего разрешённого прохода. Паспорт пилота используется для происхождения и разделения имён, не для карты мест. Нельзя заранее задавать число единиц, их статусы, состав повторений или группы по старым outputs либо Деяниям.

Предпочтителен отдельный рабочий чат **«IP-001 — Researcher Romans»**, не ветки IV Candidate/Assessor Деяний и не эта ветка Lead. Он не называется независимым предметным проверяющим. До работы раскрываются ранее виденные исторические выводы и межветочная память; свежий чат не считается автоматически полностью изолированным. При существенном раскрытии answer key — STOP до решения Lead/Owner о допустимом контроле или замене исполнителя.

Досрочное локальное историческое сравнение не предусмотрено. Первый допустимый момент подготовки сравнения — принятые Stage 0–3 по всей книге и неизменяемый snapshot новых outputs с coverage, ID, версиями, ограничениями и открытыми вопросами. Сам snapshot не открывает историю: нужен отдельный точный gate Owner. Сравнение затем существует отдельным слоем с обеими версиями; совпадение не повышает уверенность само по себе, существенное расхождение получает новый вопрос и адресный возврат без стирания исходного решения.

**Минимальная проверка без нового отдельного CV-цикла:** после разрешения Stage 0 Researcher в начале результата кратко восстанавливает Lock, доступ к рабочему тексту всей книги, историю экспозиции и пять правил работы с посланием:
1. границы единицы определяются доводом и контекстом; местоимение не разрешается оторванным стихом;
2. формулы «во Христе», «через Христа», принадлежность/роль не тождественны непосредственному действию;
3. цитата Писания, молитва, пожелание, наставление и утверждение автора различаются;
4. прошедшее событие, продолжающееся действие и будущее не смешиваются; время написания послания после Вознесения само по себе не датирует каждое упомянутое действие;
5. субъект «Бог», «Господь», Дух, Христос, человек или неясный референт именуется в пределах текстового основания.

Это проверка операционного понимания и источниковой готовности, **не доказанный предметный PASS**. Нет доступа ко всему рабочему тексту или нарушена изоляция — карта не объявляется COMPLETE. Ошибка в понимании дисциплины возвращается адресно, без запуска анализа нескольких отрывков «ради готовности».

Способность к локальному исследовательскому суждению проверяется далее на **первой естественной единице Stage 1**, взятой из принятой новой карты, перед остальным Stage 1; это часть будущего разрешённого этапа и его внутренней приёмки, не отдельная проба с историческим ключом и не независимая валидация. При материальной ошибке субъекта/посредничества — STOP и конкретный возврат. Число тестовых отрывков и их loci заранее не навязываются. Способность к Classification и книжному синтезу не выводится из успеха Stage 0.

## 5. Последовательность и критерии приёмки

Ниже — минимальные функции, а не четыре новых универсальных постоянных шаблона. Договор Stage 0 имеет ID **ROM-S0-OC-v0.1** (§5.1). Stage 1 наследует действующий Contract v0.2. Для Stage 2–3 действуют Protocol §§7,10–11 и критерии §§5.3–5.4; отдельные постоянные contracts вводятся лишь при выявленной потере функции.

### 5.1. Stage 0 — ROM-S0-OC-v0.1

**Операция:** последовательный просмотр Рим. 1–16 по RST и Criteria, без составленной заранее карты кандидатов.

**Требуемый цельный результат:** rr-000_Romans_Stage0_Corpus_Map.md:
- версии, рабочий источник/носитель, дата доступа, точная доступная редакция или честное ограничение её идентификации; при возможности фиксированная копия/контрольная сумма;
- coverage ledger всех 16 глав: просмотрена/точный пробел, диапазоны с существенными поводами или обоснованное отсутствие таких поводов;
- карта кандидатов: уникальный локальный ID ROM-C001… по факту обнаружения, locus, критерий 1–5, краткая русская причина дальнейшего изучения; необходимая контекстная/отрицательная граница и «Требует проверки» только при реальном поводе;
- раздельная временная/речевая неопределённость там, где она влияет на релевантность;
- список вопросов по §6, disclosure изоляции и краткая готовность по §4.

Отбор не устанавливает окончательный субъект, INCLUDE/BORDERLINE/CONTEXTUAL/EXCLUDE, группы или книжный вывод. Явно нерелевантные места можно предварительно исключать; отдельная карточка каждого стиха не требуется.

**ACCEPT STAGE 0** возможен, если все главы действительно просмотрены, значимые кандидаты и их причины восстанавливаются, нет answer key/предрешённых решений, пробелы не скрыты, рабочий источник прослеживаем, вопросы и изоляция сохранены. Неустранённый существенный coverage gap означает RETURN/BLOCKED, не формальный COMPLETE. При нулевом положительном результате карта может быть принята на тех же основаниях.

**Возврат:** Researcher → Lead с цельным immutable target и handoff в книжный журнал → Owner для следующего разрешённого объёма. Stage 1 не запускается одним статусом ACCEPT.

### 5.2. Stage 1 — первичные наблюдения

Входы: принятая новая карта, RST, Protocol/Criteria, Contract v0.2 и накопленный контекст только текущего прохода. По каждой существенной единице: locus/релевантное текстовое основание → субъект и ясность → способ участия → статус → русское наблюдение → существенное ограничение/вопрос. Цитирование, вид речи и временная привязка видимы там, где определяют вывод.

Перед продолжением после первой естественной единицы Lead проверяет предметную дисциплину по §4 и пять quality tests Contract §18. Затем оценивает полноту всей стадии. Каждый ROM-C-ID имеет результат или точную ссылку на обоснованное исключение; новые пропуски получают новый ID и происхождение «найдено на Stage 1», а не задним числом переписанную карту. Все содержательно существенные вопросы/отрицательные и сильные единичные основания сохранены. Нерешённое место остаётся нерешённым; для продолжения несвязанного материала при блоке требуется явный PARTIAL STOP.

### 5.3. Stage 2 — повторения, единичные и ограничивающие основания

Сравниваются только принятые локальные наблюдения этой книги. По каждому реальному повторению: состав, ссылки на основания, что именно повторяется и предел независимости. Повторение слова/формулы и несколько ссылок на одну аргументацию не выдаются автоматически за несколько независимых действий. Не создавать повторение, если основание только одно.

Критерий приёмки: все существенные наблюдения находят маршрут в повторении, сильном единичном основании, ограничении/неповторении или открытом случае; прямое/опосредованное действие и отношение не смешаны. Количество R/S/NB/NM Деяний сюда не переносится; технические IDs выбираются только по фактическому материалу.

### 5.4. Stage 3 — предварительные группы

Группа содержит русское определение, внутреннюю связь, тип основания, состав со ссылками на Stage 1–2, различия/пересечения, отрицательные ограничения, альтернативное распределение при реальном основании и зависимые вопросы. Число групп не задано; отдельное единичное свидетельство может остаться вне группы.

Приёмка: локальный путь к каждому существенному основанию сохраняется; группа отношений/ролей не названа доказанным прямым действием; открытый вопрос не получает разрешения от группировки. После принятия фиксируется новый Romans Stage 0–3 snapshot, а не переименование пилота. Это ещё не проверенный книжный итог и не Stage 4.

### 5.5. Последующие gates

Stage 0–3 исследовательски последовательны; каждое следующее исполнение требует адресного назначения и достаточного полномочия, но протокол не требует лишнего Owner-подтверждения каждого технического handoff. Предлагаемое сейчас решение разрешает **только Stage 0**, не весь цикл.

Material Verification, независимая предметная проверка, Draft Stage 4, аудит книжного закрытия и Owner recognition — отдельные установки. Для этого книжного цикла сохраняется различение: после отдельно разрешённого Draft Stage 4 → независимый предметный Review → независимый Book-Level Close Audit → Owner recognition. Нынешний Auditor имеет Scoped Active только Formation/Installation Audit; книжный audit не считается доступным автоматически. Принятый Stage 3 не снимает эти зависимости.

## 6. Собственный журнал вопросов Римлянам

**Начальное состояние: исследовательских вопросов нового прохода ещё не зарегистрировано, поскольку проход не выполнялся. Это не утверждение «в книге нет проблем».** Одиннадцать V/O Деяний остаются только в ACTS; конкретные библейские вопросы из пилота не заимствуются.

На Stage 0 раздел «Открытые вопросы Римлянам» ведётся внутри rr-000, затем при реальном накоплении — отдельный Romans/OPEN_QUESTIONS.md с ссылкой из паспорта. Отдельный пустой файл сейчас не нужен. ID **ROM-Q001…** не переиспользуется после закрытия. ROM-C-ID обозначает кандидатный locus, ROM-Q-ID — вопрос; связь может быть многие-ко-многим.

Минимальная запись при появлении вопроса:
| Поле | Содержание |
|---|---|
| ID / происхождение | новый ROM-Q-ID, этап/автор/target/commit, дата |
| Locus / связанные единицы | точное место и ROM-C/последующие ссылки |
| Вопрос / конкурирующие возможности | по-русски; различить наблюдение и предположение |
| Возможное влияние | субъект, тип участия, статус, временная граница, сила единичного основания, группа или книжный вывод |
| Нужная проверка / источник | CTX / LANG / TEXT либо конкретный иной повод, не полный разбор по умолчанию |
| Статус / owner / решение | открыт / отложен / разрешён с основанием / признан нематериальным с причиной; кто отвечает и какой gate |

Новый вопрос добавляется с первой стадии обнаружения; пропуск ранней карты не маскируется. При переносе между стадиями ID и происхождение сохраняются. Объединение вопросов сохраняет aliases; закрытие требует ссылки на разрешённую проверку и решение, не удаления строки. «Нематериальный» — обоснованное ограничение влияния, не замена нерешённого материального вопроса. Общая межкнижная карта позднее может ссылаться на ROM-Q/ACTS, но не сливает их автоматически.

## 8. Audit plan, STOP и предел проверки

IP-001 — большой проект; Independence and Audit Standard предусматривает Pre-Launch Installation Audit. Прежний аудит установки Деяний не считается автоматическим audit PASS нового пакета.

**Рекомендуется один ограниченный аудит новой Installation**, без повторного Formation всего IP-001 и без открытия исторических библейских выводов. Аудит активирует Director по §Activation hierarchy; Lead подаёт AUDIT REQUESTED, но не назначает независимую проверку собственного результата. Предмет проверки:
1. соответствие Protocol/Methodology и исследовательскому вопросу;
2. изоляция также пилотных rr-* и отсутствие перезаписи;
3. соразмерность проверки готовности к посланию и точность controlled Corpus Mapping authority;
4. coverage/переходы/свой журнал вопросов;
5. ресурсные зависимости и сохранение будущих review/close gates.

Verdict — PASS / PASS WITH CONDITIONS / RETURN / BLOCK / ESCALATE. PASS WITH CONDITIONS открывает Stage 0 лишь при документально выполненных pre-launch условиях; содержательный RETURN исправляется цельной новой редакцией, а re-check ограничивается findings и новыми материальными отклонениями. Lead принимает замечания и фиксирует исправления, не выдаёт self-check за audit.

**STOP / точный возврат:**
- потеря доступа к источнику/существенного coverage, неясный мандат или противоречие норм → Researcher к Lead, далее Director/Owner по границе;
- чтение исторического answer key до snapshot, необъявленная экспозиция или потеря provenance → остановить затронутую работу, сохранить output, раскрыть влияние; не маскировать как fresh;
- смешение субъекта/отношения/посредничества/времени, невосстановимое основание или преждевременная классификация → адресный RETURN; материальная неопределённость не исправляется языковой косметикой;
- потребность в независимой проверке без достаточного ресурса → материальное решение не закрывать; продолжать несвязанное лишь по явному PARTIAL STOP и не объявлять книжный итог;
- Stage 4, историческое сравнение, межкнижный синтез, изменение Protocol/Methodology/общего допуска → отдельный Owner gate.

В этой Installation выполнена документальная сверка норм, состояний журналов и имён файлов. Библейский текст Римлянам и исторические исследовательские outputs не открывались; локальные суждения и карта не формировались. Это внутренний self-check, **не независимый audit и не capability PASS**. RQ-RL-002 не затронут.

## 9. Точное предлагаемое решение Owner

**Рекомендация — утвердить пакет и разрешить только условный запуск Stage 0 после ограниченного Installation Audit.** Это позволяет не запрашивать второе одинаковое одобрение при чистом audit PASS.

Предлагаемый полный текст:

> Утверждаю ROMANS-BC-INSTALL-v0.1 по закреплённой редакции. Поручаю Director активировать отдельный ограниченный Installation Audit по §8. Разрешаю только контролируемый Stage 0 Послания к Римлянам: Researcher v0.1, Package C, Corpus Mapping по ROM-S0-OC-v0.1, после PASS либо выполнения всех pre-launch условий PASS WITH CONDITIONS. До этого Researcher и Stage 0 не запускаются. Lead v0.1 после документального закрытия audit gate фиксирует адресное назначение и обеспечивает передачу в ветку «IP-001 — Researcher Romans», принимает/возвращает результат → Owner. Это разрешение конкретного ограниченного применения, не общий допуск режима и не полномочие на Stage 1–3. Если аудит требует изменения объекта, authority или существенного риска, либо даёт RETURN/BLOCK/ESCALATE с незакрытым material finding, вернуться Owner; автоматического запуска нет. Пилотные outputs не открывать; Деяния C0/MV, историческое сравнение, независимую предметную проверку, Stage 4 и книжное закрытие не активировать.

**Сейчас этот текст — только предложение, не разрешение.** Альтернатива Owner: вернуть пакет с точным замечанием или отложить цикл. После утверждения одна ссылка на проектный handoff передаётся Director; он получает актуальный конец журнала и закреплённый пакет. После закрытия аудита Lead оформляет полный Stage 0 assignment в Romans/DECISIONS.md с действительным источником разрешения; Owner передаёт Researcher одну ссылку, без сборки инструкций из чатов.

**Итог:** INSTALLATION PREPARED / AUDIT REQUESTED, NOT ACTIVATED / OWNER GATE. Stage 0–3 нового цикла не выполнялись. **Ownership возвращён Owner.**
